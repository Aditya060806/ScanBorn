In one paragraph: the phone uploads depth frames to the **orchestrator** (FastAPI, one process,
SQLite), which fuses them, segments the cloud by geometry, builds a free / blocked / unknown grid
sized for the robot, plans missions on it, trains and gates a controller in a differential-drive
simulation, and quantizes it. A deploy either runs the simulated robot in-process or talks the rover
protocol to a rover (the in-process fake rover, or the ESP32 over WiFi), which runs the control loop
itself while the orchestrator relays its telemetry to the dashboard.
